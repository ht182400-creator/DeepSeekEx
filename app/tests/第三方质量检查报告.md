- 报告版本：v2.0（2026-11-24 第二轮，覆盖率提升至 97% 并引入 ESLint）
- 被测项目：DeepSeekEx（`app/` = FastAPI 后端 + 原生 JS 前端 + Go/Node PoW 求解器）
- 检查理念：**用业界标准工具做客观量化评估，替代"自己写测试自己判通过"的主观验证**

## 一、为何要引入第三方测试标准（动机与决策依据）

### 1.1 原有测试方式的局限

在引入第三方标准之前，项目测试依赖：
- 自研测试脚本（`verify_e2e.py`）+ 手工浏览器验证
- 自己写断言、自己看输出、自己判定"通过"

这种方式存在三个结构性问题：

| 问题 | 具体表现 | 后果 |
| --- | --- | --- |
| 标准不客观 | 断言覆盖什么、不覆盖什么全凭作者判断 | 容易"测了自己想测的，漏了真实会坏的" |
| 覆盖不可量化 | 不知道有多少代码从未被执行 | 无法回答"质量到底到什么程度" |
| 静态风险盲区 | 不做静态分析和安全扫描 | 未使用导入、异常吞噬、硬编码凭据等靠肉眼发现 |

### 1.2 选择标准的原则

1. **事实标准优先**：选业界广泛使用、CI 原生支持的工具，而非小众工具
2. **互补覆盖**：语法/风格、安全、运行时行为、覆盖率、前端各一维，不重复也不遗漏
3. **可量化、可卡口**：每条标准都要有明确阈值，能拦截回归
4. **误报可治理**：允许豁免，但每条豁免必须写明理由，避免"为了绿而绿"

### 1.3 引入后的收益（实测）

- 静态分析从 0 工具 → Ruff 修复 75 个问题（含真实 bug：死代码、异常吞噬）
- 安全从 0 扫描 → Bandit 识别 6 处并逐条定性
- 覆盖率从"未知" → 量化到 25% → 补测后 **97%**
- 发现并修复了一个**真实的字段迁移 bug**（TC-M04，详见第六节）
- 前端从"只做语法检查" → ESLint 静态分析，发现并修复一处缺失的错误日志

## 三、为何选择这些工具（逐个说明）

### 3.1 Ruff —— Python 静态分析

- **选择理由**：用 Rust 实现，比 Flake8/Pylint 快 10-100 倍；将 pycodestyle、Pyflakes、isort、pyupgrade、bugbear、pylint 等规则统一在一个工具；原生支持 pyproject.toml 与逐文件豁免
- **替代了什么**：替代手工检查未使用导入、导入顺序、类型注解现代化
- **规则集选择**：精选 E/W/F/I/UP/B/SIM/PIE/PL/G/S 十类（见 5.1），不启用 ALL（ALL 含 D/ANN/T20 等与项目风格冲突的规则，会产生数百个无意义告警）

### 3.2 Bandit —— Python 安全扫描

- **选择理由**：Python 安全扫描的事实标准（OpenStack 出品），专门检测硬编码口令、不安全的 subprocess、异常吞噬等；与 Ruff 的 S 规则互补（Bandit 更专注于安全语义，能识别配置字段中的空字符串口令等上下文）
- **检测到的真实风险**：`try/except/pass` 静默吞异常（已修复为告警日志）；subprocess 调用需确认输入可信性（已定性为固定本地路径并豁免）

### 3.3 pytest + coverage —— 测试运行与覆盖率

- **选择理由**：pytest 是 Python 测试事实标准，支持 `subtests`（数据驱动案例）、`IsolatedAsyncioTestCase`（异步 provider）、fixture 与参数化；coverage 是唯一广泛接受的覆盖率工具
- **为何要量化覆盖率**：25% 的初始覆盖率暴露了"main.py 从未被导入测试"这一盲区——这正是自研测试发现不了的问题
- **阈值演进**：70%（初版）→ 90%（补测后），每次提升都基于实测数据而非拍脑袋

### 3.4 为何要引入 ESLint（重点说明）

- **背景**：前端是 4 个原生 JS 文件通过 `<script>` 顺序加载，无构建系统、无模块化。此前只做 `node --check` 语法检查
- **为何语法检查不够**：`node --check` 只能发现语法错误，发现不了：
  - 使用了未定义的变量（拼写错误的函数名 → 运行时崩溃）
  - `==` 与 `===` 混用导致的隐式类型转换 bug
  - 定义后从未使用的函数（死代码）
  - `catch` 块拿到异常却不记录（静默失败）
- **选择 ESLint 10 的理由**：
  - JavaScript 静态分析的绝对事实标准，所有主流 CI 原生支持
  - v9+ 扁平配置（Flat Config）比旧版 `.eslintrc` 更清晰
  - 可通过 `globals` 声明原生脚本的跨文件共享标识符，适配本项目架构
- **引入后的实际收益**：
  - 配置过程中发现并修复一处真实缺陷：`app.js` 删除会话失败的 `catch (exc)` 未使用异常对象、未记录日志 → 补充 `logError('删除会话失败: ' + exc)`，符合项目日志规范
  - 配置完成后 0 error / 0 warning，前端代码质量有了可卡口的基线
- **配置要点**（为何需要大量 globals 声明）：
  - 项目是脚本而非模块，`data.js` 定义常量、`utils.js` 定义工具函数、`actions.js` 定义操作函数、`app.js` 使用它们
  - ESLint 默认按单文件作用域分析，不声明 globals 会把跨文件引用误报为 `no-undef`（首轮报 125 个 error，全是误报）
  - 声明 39 个项目全局名后，真实错误清零
  - 对 `data.js`/`utils.js`/`actions.js` 关闭 `no-unused-vars`（其导出项供其他脚本使用，单文件内看似未用是架构特性）
