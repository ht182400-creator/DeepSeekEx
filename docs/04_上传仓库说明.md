# 仓库上传说明（GitHub / Forgejo）

本文档说明本项目上传到公开仓库（GitHub、Forgejo）时的范围、安全边界与操作步骤。

## 一、上传范围

### 1.1 必须上传（源码 + 文档）

| 路径 | 内容 |
| --- | --- |
| `README.md` | 项目说明、启动、首次准备、文档索引 |
| `start-servers.bat` | 一键启动脚本 |
| `.gitignore` | 忽略规则（防止误传凭据/安装包） |
| `app/*.py` | `config.py` / `main.py` / `providers.py` / `pow_solver.py` |
| `app/frontend/` | `index.html` + 4 个 JS + `styles.css`（**不含** `node_modules/`） |
| `app/pow-go/main.go` | Go 求解器源码（**不含** exe） |
| `app/pow-node/solve.js` + `package.json` + `package-lock.json` | Node/WASM 求解脚本（**不含** `node_modules/`） |
| `app/data/settings.example.json` | 配置模板（**无真实凭据**） |
| `app/bandit.yaml` / `pyproject.toml` / `pytest.ini` | 第三方质量工具配置 |
| `app/run_quality_checks.bat` | 统一质量检查入口 |
| `app/tests/*.py` + `test_patch_cases.json` | 测试源码（**不含** `logs/` / `coverage.xml`） |
| `app/tests/*.md` | 测试案例库与质量报告（已脱敏） |
| `docs/` | 产品报告、设计说明、PoW 方案、本文档 |

### 1.2 禁止上传

| 路径/类型 | 原因 |
| --- | --- |
| `app/data/settings.json` | 含真实 `web_token`（64 字符登录态凭据） |
| `app/data/chats.json` | 真实对话历史（含个人查询记录） |
| `tools/`（199MB） | Go 工具链安装包，仅编译时需要 |
| 所有 `node_modules/` | npm 依赖，可 `npm install` 复原 |
| `*.exe` / `*.dll` | 预编译二进制安装包 |
| `app/logs/` / `app/tests/logs/` / `*.log` | 运行日志，含请求信息与时间戳 |
| `coverage.xml` / `.coverage` | 测试环境产物 |
| `__pycache__/` / `*.pyc` | Python 编译缓存 |
| `.codebuddy/` | 本机开发数据（含本机路径等非公开信息） |
| `replica/`、`enhanced/` | 早期静态原型，非必须代码 |
| 公钥/密钥指纹、邮箱式主机标识、本机绝对路径、私钥文件名相关内容 | 用户明确规定：公钥/指纹/本机路径/账号名不得写入公开仓库 |

## 二、上传前检查清单

上传前逐项确认（命令在项目根目录执行）：

```powershell
# 1. 确认无敏感信息残留（期望：无输出）
# 用拼接方式构造关键词，避免本检查文档本身被扫描器误报
$P1 = 'SHA' + '256:'; $P2 = 'C:' + '\Users\'; $P3 = 'id_' + 'rsa'; $P4 = 'user' + '@host'
git grep -nE "$P1|$P2|$P3|$P4" -- '*.md' '*.py' '*.json' '*.bat'

# 2. 确认真实配置未被跟踪（期望：显示 ignored）
git check-ignore -v app/data/settings.json app/data/chats.json

# 3. 确认安装包/依赖未进入（期望：均显示 ignored）
git check-ignore -v app/pow-go/pow-solver.exe app/frontend/node_modules tools

# 4. 确认示例模板会被上传（期望：无输出，即未被忽略）
git check-ignore -v app/data/settings.example.json

# 5. 预览将要提交的文件（人工核对清单）
git status --short
git ls-files
```

## 三、双平台上传步骤

两个平台使用同一份本地仓库，只是 remote 不同。

### 3.1 初始化仓库（首次）

```bash
cd <项目根>
git init
git add .
git status          # 按第 1、2 节清单核对
git commit -m "Initial commit: DeepSeek Studio 源码与文档"
```

### 3.2 推送到 GitHub 与 Forgejo

```bash
# 添加两个远端（<owner>/<repo> 用各平台实际值替换，勿写入文档）
git remote add github <GitHub 仓库 URL>
git remote add forgejo <Forgejo 仓库 URL>

# 分别推送
git push -u github main
git push -u forgejo main
```

> 说明：本机已配置认证凭据，URL 请通过 `git remote -v` 自行查询，不要在文档/提交信息中记录账号名、主机路径或密钥指纹。

### 3.3 后续同步

每次改动后：

```bash
git add .
git commit -m "描述本次改动"
git push github main
git push forgejo main
```

## 四、上传后验证

在 GitHub 与 Forgejo 网页端分别确认：

- [ ] 仓库文件列表不含 `settings.json` / `chats.json` / `tools/` / `node_modules/`
- [ ] `app/data/settings.example.json` 存在且 `api_key`/`web_token` 为空字符串
- [ ] 按第二节命令扫描，文档无本机路径 / 账号名 / 密钥指纹残留
- [ ] README 的启动步骤在新环境可执行（按"三、上传后首次准备"）
- [ ] 两个平台内容一致（`git log -1` 的 commit hash 相同）

## 五、已知限制（发布说明）

- 网页登录态接口为非公开协议，可能随 DeepSeek 更新失效；官方 API 更稳定合规
- 预编译 PoW 二进制不上传，需本地编译或回退（Go ~13ms / Node WASM ~18ms / 纯 Python ~16s）
- 本项目仅供本机使用（服务绑定 `127.0.0.1`，端口 20000）
